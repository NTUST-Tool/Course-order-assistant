# 課程監測功能指南

[返回專案介紹與選課分析教學](../README.md)

監測功能會定期查詢指定課程的人數，發現空缺時在本機提醒，並透過 ntfy.sh 發送通知。它不會代替你登入或操作選課；空缺、資格限制與實際選課結果仍以學校系統為準。

## 開始使用

1. 啟動程式，在主選單選擇 `2`（執行課程監測功能）。程式會先取得目前學期。
2. 複製畫面上的 `ntfy topic`。它是 64 個隨機十六進位字元；不需要輸入學號，也不使用硬體識別資料。
3. 在手機的 ntfy app 新增訂閱，伺服器使用 `https://ntfy.sh`，頻道填入剛才複製的完整名稱。允許 app 顯示通知，並確認手機可以連線。
4. 輸入課程代碼，多個代碼以逗號分隔，例如 `CS1001301, EE2003501`。可有空格，英文小寫會轉成大寫；代碼格式為 9 個字元。範例只示範格式，不保證目前學期開設這些課程。
5. 輸入查詢間隔，直接按 Enter 使用預設 5 秒。開始監測後，保持程式與網路連線開啟。

ntfy app：[Android](https://play.google.com/store/apps/details?id=io.heckel.ntfy)、[iOS](https://apps.apple.com/app/ntfy/id1625396347)。安裝後仍須自行訂閱，程式不會替手機完成訂閱或通知權限設定。

之後再次啟動會沿用已保存的頻道，並詢問是否使用上次的課程清單。看到「通知頻道已升級」提示時，請訂閱當次顯示的頻道；全新設定第一次產生頻道時也會顯示此提示。

## 查詢間隔與退出

| 輸入 | 間隔 |
| --- | --- |
| `5` | 5 秒 |
| `10m` | 10 分鐘 |
| `1h` | 1 小時 |
| `1h30m` | 1 小時 30 分鐘 |
| `2h30m50` | 2 小時 30 分鐘 50 秒 |

有效範圍為 1 秒至 24 小時；過大或無效的輸入會要求重新輸入。程式每輪依序查詢課程，完成後等待設定間隔加減最多 2 秒，實際等待至少 1 秒。因此兩輪之間還包含查詢與重試所花的時間，不是固定頻率。

等待時會顯示倒數。監測啟動後，輸入 `Q` 或 `q` **再按 Enter**，可取消查詢、重試或等待並返回主選單；在主選單選擇 `0` 結束程式。只按 Q 而不按 Enter 不會退出。輸入來源關閉時，程式也會正常結束。

請依課程數量與實際需要設定間隔，避免過度頻繁地查詢。隨機延遲不代表不會受到學校的流量限制。

## 提醒與通知規則

- 本機每輪發現空缺時會顯示提醒並發出三聲嗶聲；聲音是否播放取決於終端機設定。
- 每門課第一次發現空缺時，嘗試立即發送 ntfy 通知；之後若空缺持續存在，每隔至少 5 分鐘再發送，最多成功發送 12 次。
- 空缺通知失敗會顯示錯誤，不會扣掉成功通知次數，可在下一輪再嘗試。實際送達時間還受查詢間隔、網路及 ntfy 服務影響。
- 課程從有空缺變成滿額時，會嘗試發送一次滿額通知，並重置該課的空缺通知計數。再次出現空缺時重新計算。
- 計數只保留在本次監測期間；退出後重新開始會重置，不受已保存的頻道影響。
- 通知包含課程名稱、上課時間、人數與通知次數。收到提醒後仍需自行到學校系統選課；收到通知不代表已保留名額。

## 設定保存與隱私

設定保存在**執行檔所在目錄**的 `course_assistant_config.json`，包含通知頻道及上次的課程清單。移動或替換執行檔時，請保留並一併搬移此設定檔；若新位置沒有設定檔，就會產生不同頻道，需要重新訂閱。

設定檔不存在時可建立新設定；讀取失敗、內容損壞或無法寫入時會顯示錯誤並停止該次操作，不會默默改用預設值。儲存時先寫完整的新檔案，再替換原檔；Unix 檔案只允許擁有者存取，Windows 的存取權限依所在目錄設定。

頻道使用 256 位元隨機值，難以猜中，但**不是加密或存取控制**。取得頻道名稱的人可能可以訂閱或發送訊息；ntfy 服務也會收到通知內容。不要分享頻道或設定檔，不要在公開截圖、問題回報或 Git 提交中包含它們。

### 曾使用舊測試版的人

本節只適用於已經有舊版通知設定的人，一般首次使用者不需要額外遷移。

若設定使用過學號衍生頻道，或有 `course-` 前綴的 71 字元隨機頻道，程式會更新為目前支援的名稱並提示重新訂閱。舊頻道不再接收這個程式的新通知，請改訂閱畫面上的完整頻道。遇到設定損壞時，先做私人備份再處理，不要直接刪除而失去原設定。

## 疑難排解

| 狀況 | 建議處理 |
| --- | --- |
| 無法取得學期或課程資料 | 確認學校查詢服務與網路是否可用。單次請求最多等待 20 秒，連線階段最多 10 秒。每門課最多嘗試 3 次，中間等待 2 秒、4 秒。 |
| 課程代碼被拒絕或查無課程 | 檢查完整代碼及目前學期；格式正確不代表該學期有開課。 |
| 設定無法保存 | 確認執行檔目錄可寫入，並檢查設定檔內容；備份時也要保密。 |
| 畫面顯示通知發送失敗 | 先確認網路及 ntfy 服務。空缺通知可在下一輪再嘗試。 |
| 程式顯示已發送，但手機沒有通知 | 確認伺服器為 ntfy.sh、頻道完整相同，並檢查 app 訂閱、網路、通知權限與省電限制。服務接受訊息不代表手機一定已顯示通知。 |

無法排除時，請到[專案 Issues](https://github.com/NTUST-Tool/Course-order-assistant/issues) 回報平台、執行方式及已遮蔽敏感資料的錯誤訊息。

## 從原始碼執行

若下載版本尚未包含監測功能，可取得包含此功能的原始碼後自行編譯。已使用 Rust 1.95 與 1.96 驗證；建議使用這些版本或更新的穩定版，不將未驗證的版本宣稱為最低需求。

在專案根目錄執行：

```sh
cargo build --release --locked
cargo run --release --locked
```

Windows 執行檔為 `target/release/Course-order-assistant.exe`；macOS/Linux 為 `target/release/Course-order-assistant`。程式顯示主選單後選擇 `2`。

## 維護者驗證

```sh
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
cargo build --release --locked
```

預設測試只使用本機通知測試伺服器，不會向公開頻道發送訊息。學校連線可另外驗證：

```sh
cargo test --locked live_semester_https_request -- --ignored --nocapture
```

**取得明確允許對外發送後**，才執行以下 ntfy 真實收發測試。它會建立隨機頻道的串流訂閱，透過實際發送函式送出一則純測試訊息，再核對收到的內容；不需要手機，也不能代替 iOS/Android 的通知顯示驗證。

```sh
cargo test --locked live_ntfy_subscription_roundtrip -- --ignored --nocapture
```

Windows、Linux GNU 與 Linux musl 的編譯及基本操作已驗證。發布目標與建置步驟以[現有 CI 設定](../.github/workflows/ci.yaml)為準；公開版本是否已包含監測功能，仍應查看發布說明。
